# RuriBridge

> ## 🟧 Blender 在中间,另外两个补它的短板
>
> **建模在 Blender**,它是模型唯一的作者。另外两个软件不改模型,各自把自己那半交回来:
>
> | | 拿走 | 交回来 |
> |---|---|---|
> | **Substance 3D Painter** | 绘制表面 | 通道贴图 |
> | **Cascadeur** | 绑定 + 当前动作 | 做完的表演 |

跨进程的载荷落在一个共享的「竞技场」目录里:一份定长控制块(每条通道一个 seqlock 槽)加上
不可变的 generation 目录,写满才发布,所以读者永远不用对载荷加锁。文件都带
`FILE_ATTRIBUTE_TEMPORARY`,对面紧接着就读,页从缓存出,不走一遍写回再读出。

**检出就住在 Blender 的 addons 目录里**,仓库根即插件;Painter 用目录联接指回来,
Cascadeur 收一份生成的入口脚本。一份代码,不复制、不分叉。

```
<Blender scripts>/addons/RuriBridge/
  __init__.py        宿主检测 + 分派
  Kernel/            宿主中立,纯标准库:花名册、主题、会话、竞技场、通道、记录、命令行
  Host/
    Blender/         唯一允许 import bpy 的地方
    Substance/       唯一允许 import substance_painter / PySide 的地方
    Cascadeur/       唯一允许 import csc 的地方
```

## 怎么用

**什么都不会自己发生。** 每一次过桥都是有人在某一边按了按钮。

两边的按钮完全对称:同一件事从哪边按,结果都一样,只是一边叫推送、另一边叫拉取。
**选中**在 Painter 里是当前选中的纹理集,在 Blender 里是活动物体的活动材质画进的那个纹理集;
**全部**是每个纹理集。

着色器和贴图分开推拉:

| 做什么 | Blender | Painter |
|---|---|---|
| 网格:只换网格本身 | Update Mesh | Update Mesh |
| 着色器 + 全部参数:Blender → Painter | Push All / Selected Shader | Pull All / Selected Shader |
| 着色器参数:Painter → Blender | Pull All / Selected Shader | Push All / Selected Shader |
| 材质自己的贴图:Blender → Painter | Push All / Selected Textures | Pull All / Selected Textures |
| Painter 画的 → Blender 的材质 | Pull All / Selected Textures | Push All / Selected Textures |
| Painter 选中的那一层 → Blender(只是图片) | Pull Selected Layer | Push Selected Layer |
| 纹理集换到另一套 UV 布局,图层全留 | UV Layout ▸ Source UV / Target UV ▸ Retarget | — |

- **Update Mesh**:把绘制表面发给 Painter。Painter 没开工程就用它新建一个;开着就换网格,
  每个纹理集的图层一层不动,别的什么都不改。这一发会在已经画过的工程里**新建纹理集**时先问一句:
  新集上什么都没画,如果是某个材质改画进了新集,它的面在原来那个集里的画就不再显示(图层还在)。
  没有材质的面不发 —— 桥不替你建材质(建出来的名字没人起过,还会改掉物体的渲染);面板列出这些物体。
- **着色器 Blender → Painter**:纹理集换上画它的那个材质的着色器,写入全部参数;身份不同只写同名
  参数(见下文「材质:身份决定搬多少」)。不碰图层、不碰贴图。材质不在生成着色器上的纹理集跳过并说明。
- **着色器 Painter → Blender**:纹理集着色器实例上的参数,按材质自己的声明反向写回材质记录
  (伽马色还原成作者值,材质常量不动);材质照记录更新。从库 link 进来的材质写不进去,先本地化。
- **贴图 Blender → Painter**:按着色器清单把材质的贴图切进纹理集(见下文),只在货架上是同一代
  着色器时做;没有图层的纹理集(比如补回一张脸)就靠这一下初始化,然后在上面补画。
- **贴图 Painter → Blender**:导出到 .blend 旁边的 `textures` 文件夹,接进画进那个纹理集的
  材质里;生成材质按它自己着色器的贴图布局重新拼好再换进它的记录(见下文「贴图」)。
- **选中的那一层**:单独导出,进来的是图片,不接进材质 —— 一层不是材质该显示的全部,接进去就把
  完整结果顶掉了。
- **一张表**(Blender 面板):每个材质画进哪个纹理集,两边都能改。
- **Retarget**(Blender 面板 UV Layout 一节):设好 Source UV(纹理集现在排在哪套)和 Target UV
  (新布局在哪套),活动材质画进的纹理集就从源换到目标,Painter 里每一层都留着(见下文「UV 布局重定向」)。
- **Pull Mapping**(Blender 面板里折叠的一节):不是生成器做的材质,在这里指定每个贴图节点从
  Painter 的哪张图来 —— 整张原样拿,或者 R/G/B/A 逐通道取某张图的某个分量(可取反:光滑度 =
  1 − 粗糙度),各家工作流的打包遮罩就这样拼,叫什么名字都行。整张原样的节点直接用 Painter 导出的
  那个文件;逐通道的在 `textures` 里拼成 `<纹理集>_<节点>.png`。规则和生成材质一样:一张图整片
  一个值(没画过)就不动节点原来的图,标「保留」的通道留节点原图的那一分量。表记在材质自己身上
  (`ruri_bridge_channels`);第一次改时先按现有的按名字落点填好,别的节点照旧;**Land By Name**
  删表,回到按节点标签落点。生成器的材质不用表,按它着色器的清单一一对应。Painter 在在场记录里报出
  每个纹理集会导出哪些图,所以拉取之前就能选。

Painter 另有:

- **Pull a Blender image into the selected layer**:把 Blender 材质用到的一张图放进选中的图层,
  作为遮罩或参考填充。Blender 没有图层,所以从那边来的东西只可能是这两种形状,而且只碰选中的那一层。
  选中的接不了(没选、选了好几个、参考却选了绘画层)就**新建一个填充层**装它,放在选中层上方
  (没选就放最上面),只开底色通道 —— 不拿缺省值盖住下面各层的其他通道。
  拉的是磁盘上的那份文件:Blender 里改过还没存的图,先存盘再拉。
- **同一张表**:纹理集 / 图层数 / 由哪个 Blender 材质画。有图层却没有材质画它的纹理集标成橙色 ——
  下一次换网格会在它这里停下;要放弃它,勾上 **Drop**(只对下一次换网格有效)。

## 纹理集就是名字

材质画进哪个纹理集,记在材质的自定义属性 `ruri_bridge_identity` 上。第一次过桥时抄下材质
当时的名字,从此不动 —— Blender 里改材质名只改标签,不会让 Painter 以为来了个新材质。

- 多个材质可以画进同一个纹理集(一个材质拆成两个、共用一套不重叠 UV 的情况)。
- 属性设成空字符串 = 这个材质不进 Painter(描边、毛发壳这类渲染专用材质)。面板表里每个材质后面的
  **眼睛**就是这个开关:点掉,下一次 Update Mesh 起它的面不再发;隐藏的材质列在 Materials 里,再点眼睛
  放回来。它画进的纹理集还有图层、又没别的材质画它时,换网格会在那里停下,图层不丢 —— 在 Painter 里
  删掉那个集,或者把材质放回来。
- Painter 里的纹理集名不对(外包工程常见,比如 `pCube2SG`):在表里给它选 Blender 材质。
  那个材质已经有人画进别的纹理集就并进去;没有的话,桥请 Painter **把纹理集改名成材质名**
  —— 改名是 Painter 里唯一保留全部图层的编辑。

## 绘制表面:FBX,落在工程自己的坐标系里

发过去的是**画的那个表面**:静止姿势的基础网格,带建模修改器(镜像、三角化),不带渲染时才有的
(骨骼姿势、几何节点长出来的描边壳和毛发层)。按原始多边形写,让 Painter 自己三角化。UV 集 0 是
Blender 渲染用的那套 UV —— 纹理集画在它的布局里;后面的 UV 集是纹理集的布局表点名的旧布局
(见下文「UV 布局重定向」)。

**工程有自己的坐标系,一生不变。** Painter 把三平面 / 平面 / 球形 / 扭曲投影都放在工程表面
第一次进来时的那个包围盒里,换网格时把笔触从旧表面上的位置重投影到新表面上的同一处。
**保留笔触**换网格就保住这个框;不保留,所有投影和多边形填充的遮罩就整体挪位 —— 哪怕新表面
只在远处多了一个三角形。Painter 只在单位和比例一致时才肯保留笔触,所以表面必须按工程的坐标系
送来:

- 桥新建的工程以厘米计(`scale = 100 × 场景单位`),坐标系写进工程元数据 `RuriBridge/frame`,
  随 .spp 存盘。
- Painter 把坐标系放在自己的在场记录里,Blender 每次发网格都写进这个坐标系。
- 别人做的工程(没有坐标系)会被拒绝,而不是猜一个:猜错会让所有 3D 画的东西挪位。
  这种工程要先量出它原本的坐标系、写进元数据(一次性),之后就和桥建的工程一样。

保留笔触也有搬不动的:**多边形选区是按纹理集里的三角形记的**,一个面换了纹理集、或者四边形
换了对角线,它那份选区就跟着走了。这是 Painter 自己的限制,有没有桥都一样。

选 FBX:glTF 的材质描述会被 Painter 的导入器变成每个新纹理集上一层没人画过的「导入的颜色」
(金属度还是 1),OBJ 只带得了一套 UV,USD 不带额外的 UV 集。桥自己写 ASCII FBX 7.4,只写顶点、
逐角法线、各 UV 集和材质名;数值一律写成 float32 能精确表示的十进制,同一个表面读两次逐位相同。

## UV 布局重定向

一个纹理集要换到另一套 UV 布局(比如把一个物体的几个材质摆进同一张贴图),Painter 里的图层
一层不删、一层不重画。

**准备**:画进这个纹理集的每个材质所在的每个网格(场景里隐藏的也算,它们显示同一张贴图),都有
两套**同名**的 UV:源 —— 纹理集现在排在里面的那套,也就是网格渲染用的那套(Painter 画在它上面);
目标 —— 装着新布局。Painter 开着这个工程,而且手里的表面就是 Blender 现在的样子(不是就先
Update Mesh —— Painter 记着它收到的每个纹理集表面的指纹,对不上就拒绝,因为网格贴图是在那个表面
上排的);.blend 存过盘。

**操作**:选中材质,UV Layout 里设 **Source UV** 和 **Target UV**(下拉列的是活动物体的 UV),
点 **Retarget**。差什么面板逐条列出来 —— 哪个物体缺哪套 UV、哪个物体渲染用的不是源、哪个物体来自库
—— 全对上按钮才亮。语义和 ShiyumeBlender 的 UV 重定向一样:在这个纹理集的面上两套 UV **互换**,
源拿到新布局、目标接住旧布局,两套都留着、名字都不变,同样的源和目标再点一次就换回来。UV1→UV2、
UV2→UV1 都行,只要源是渲染用的那套。

1. Blender 先问 Painter:显示这个纹理集的每个按 UV 集读图的填充读哪个 UV 集、还有哪些纹理集也显示
   它,各纹理集现在的布局表;交出网格贴图、经旧布局读的法线、效果直接读的图、判断法线约定用的导出。
2. Blender 先排好新的布局表:一个填充在显示它的每个纹理集里读同一个 UV 集,别的纹理集定住了它能读
   哪几个,这个纹理集就把其中一个指向此刻装着它要读的那套 UV(必要时让两个 UV 集指向同一套 UV);
   排完用 Painter 收表面时的同一个检查(`rebind`)过一遍 —— 过不去就在这里拒绝,两边什么都没动。
3. 然后一步做完:网格贴图在新布局里重排(Painter 手里留着目标布局原来的那份就直接用那份,一个像素
   都不重采);两套 UV 在这个纹理集的面上**互换** —— 源装新布局,目标装旧布局;布局表写进材质
   (`ruri_bridge_layout`);材质自己按 UV 采的图在新布局里重排、存进 `textures`;连同新网格贴图发出
   新表面。
4. Painter 换上表面:按旧布局排的内容改成通过装着旧布局的 UV 集去读(UV 集到 UV 集投影),
   换上新网格贴图;桥从材质立起来的**着色器贴图参数**按 Blender 已重排的材质再取一次 —— 着色器直接
   按纹理集的布局读它们,而 Painter 交不出贴图的原始像素;桥那一层本身和别的填充一样经旧布局去读,
   原样不动。

同样的源和目标再做一次就换回来。

**哪些完全不变**:

- 读图的填充(位图、Substance、矢量、文字)都继续读**原图原像素**,经旧布局去读,桥不重采样(只铺
  位图的填充在孤岛转动处例外,见下);遮罩里的也一样。实例层共用的内容对每个显示它的纹理集都成立。
- 平铺(UV 变换缩放、旋转、平移了图案的填充)同样经旧布局去读,变换原样保留,图案还铺在表面原来的
  位置(实测:颜色、粗糙度与原来逐像素相同)。Painter 只给经 set 0 读的旋转平铺转法线,经别的 UV 集
  读就不转 —— 旋转平铺的法线因此少转那个角度,桥连同孤岛转动一起算进报告的度数;别的纹理集也显示的
  旋转平铺若铺法线,就留在 set 0 照旧平铺,否则那些纹理集的法线也会被改。
- 遮罩里的生成器按它所在布局的网格贴图算。包里声明的图像输入 Painter 全都放给外面接(没有它自己按
  set 0 布局暗接的输入)、又只在一个纹理集显示的生成器,原地换成同一个程序化包的填充:输入、参数、
  随机种子、分辨率、混合、不透明度、名字照抄,经旧布局去读,网格贴图输入接旧布局的那几张 —— 它就
  继续在旧布局里算,结果搬到新布局(实测:曲率、污渍、边缘磨损、AO 换算后与旧布局的结果只差采样
  噪声,不换算的差到平均 0.03–0.11)。换回那个布局时,它变回原来的生成器。声明了哪些输入,桥从包
  文件本身(7z 里的描述)读出来;包文件已经不在了的生成器不动。
- 笔触与多边形填充由 Painter 换网格时按三维 / 按三角形重放;三维投影(三平面、平面、球形……)本来
  就不读 UV。
- 网格贴图(法线、AO、曲率、位置、ID……)在新布局里重排:ID 取最近的像素不混色;切线空间的
  (法线、弯曲法线)逐像素从旧布局的切线框架换到新布局的 —— 框架就是 MikkTSpace 每个角的切线与
  副切线符号按三角形插值,和渲染器解码用的同一套;多于四个角的面按渲染器拆的三角形去算。
- 程序化的内容只改映射,永远保持程序化:Substance、程序化纹理、Substance 材质照旧在旧布局里算、
  经旧布局去读,参数照旧可调,一律不渲染成图、不加任何层。
- 孤岛转了、镜像了,切线框架就跟着转(Painter 的 UV 集到 UV 集投影只原样拷法线,不换框架)。位图
  是像素,像素跟着孤岛走:原文件还在就用原文件,不在了就让 Painter 单独渲染那张图(渲染时让填充
  临时直接读 set 0,拿到的就是它在所读布局里的整张图)。只铺位图和纯色、经 set 0 读、除法线外每张图
  的原文件都还在的填充,它的每张图都在新布局里重排(法线逐像素从旧框架换到新框架)、改成经 set 0
  读,旧布局里共用像素的孤岛(镜像的两半)到了新布局各拿各的;别的填充(位图法线和程序化内容铺在
  一起的、别的图原文件已经不在的)继续经旧布局读,只把法线图**原地**逐像素从读它的孤岛原来的框架
  转到现在的框架 —— 旧布局里两块孤岛共用、又转得不一样的像素只装得下其中一块的方向,桥报出最多差
  几度。Painter 单独渲染出来的只有法线是原图本身(实测:颜色通道差到 1/255,8 位高度通道被钳在
  0.5 以上),所以别的通道只从原文件搬。桥记着每张换下来的原图在哪个布局里是对的:
  换回那个布局时填充拿回原图,来回一趟原样复原,不重采两次。材质自己的法线图同样换框架。
- 效果自己不带投影、直接在 UV 集 0 里读的图 —— 颜色选择的 ID 图、生成器和滤镜的图像输入 —— 是
  纹理集自己的网格贴图就跟着网格贴图换;别的图在新布局里重排(ID 图取最近的像素),作为那个效果的
  新图。
- 三维投影和三维的生成器(位置、世界法线……)在新布局里按每个表面点重算。旧布局里两块孤岛共用的
  像素(镜像的两半、错开一整格的复制)只装得下其中一块的结果;到了新布局各拿各的像素,那里的结果
  就是各自正确的值。
- 超出 0..1 的 UV 按重复折回(没有 UV 块的纹理集就是这样画、这样烘、这样读的),新旧布局都是。
- 重排按双线性在每个新像素中心取旧图的值,这是 Painter 自己经 UV 集到 UV 集投影读图时最接近的
  取法(实测:孤岛缩小两倍以上时也比 mip 预滤波贴合)。
- 绿通道方向全靠实测,不猜:网格贴图按工程的法线格式存,格式由 Painter 的导出读出来(它把网格法线
  和法线通道混合的公式对翻转绿通道是等变的;导出时临时在最上面盖一层把法线通道换成一个倾斜的法线、
  高度换成一个常数,每个像素都能比一下符号,不受内容里的凹凸影响);填充里的图 Painter
  按它**第一次被拿来做什么**决定怎么读(新导入、只用在填充法线通道的图按 DirectX 读,与工程格式
  无关),所以每张图都临时单独渲染一次来比,换回去的新图也先拿一张没见过的图测好读法。

**本来就跟 UV 空间走的**(换了布局图案必然不同,保留原样):

- UV 空间的滤镜(模糊、锐化、扭曲、高度转法线……):它的输入就是本层的内容,Painter 不放给外面接,
  只能在 set 0 的布局里算 —— 孤岛缩放后按 UV 单位算的强度跟着变;比较遮罩比的是下面各层,下面跟着
  变它就跟着变。
- 按 UV 孤岛算的生成器(UV 边界距离、孤岛随机色、UV 棋盘格、纹素密度、自动缝线……):包里声明了
  Painter 自己按 set 0 布局暗接的输入(孤岛遮罩 ``mesh_uv_mask``、纹素大小 ``mesh_texel_size``),
  外面接不进去(实测:``Unknown input``),所以只能按新孤岛算。别的纹理集也显示的生成器同样按 set 0
  算,它的网格贴图输入是各纹理集自己的。
- 智能材质、智能遮罩:里面的平铺、生成器、滤镜各照上面的条目。
- 程序化的切线法线:孤岛只平移、缩放时完全准确;孤岛转了、镜像了的地方凹凸的位置对,受光的方向
  却保持旧孤岛给的 —— 法线是相对孤岛 U/V 轴的方向,Painter 原样拷贝它,也没有能按像素实时转向量
  的手段(Python / JavaScript 接口、纹理集内部字段、自带滤镜都查过),不渲染成图就只能这样。别的
  纹理集也在显示的位图法线同样原样不动(它们的孤岛不跟着动)。桥完成时逐层报出来,连同那层法线
  最多偏了几度;要这些地方也准,打包时给这些孤岛关掉旋转和镜像。
- 在 Painter 二维视图里画的笔触:Painter 换网格时按三维重放三维笔触,二维笔触留在原来的 UV 坐标上
  (实测:换布局后它们落在新布局里同一处 UV 上,也就是表面上别的地方)。

**拒绝而不是猜**(说清是哪一层):按 UV 块投影的填充;UV 块工作流的纹理集;效果直接读的图、而
别的纹理集也在显示那个效果(它们的孤岛不跟着动)。

## 材质:身份决定搬多少

着色器生成器给每一条腿的产物烙同一个**身份**:风格参数面(part 词汇 × 纹理槽 × uniform 名与类型)
的散列。Blender 的生成材质把它写在 `ruri_shading.identity`,Painter 货架上的着色器把它写在旁边的
`<名字>.manifest.json`。

- 一个纹理集由**和它同名的材质**代表(多个材质画进同一个纹理集时,同一个着色器实例只能有一行值)。
- Painter 货架上同名着色器的身份**与材质声明的相同** → 纹理集换上这个着色器(每个纹理集一个自己的
  实例,共用实例装不下不同的值),整行参数原样写入。
- **不同**(别的着色器、同一着色器的另一代、或者没烙身份的旧拷贝)→ 不换着色器,只写两边**同名**的
  参数,其余的不猜,写进 Painter 日志。

货架上的着色器和清单是一个产物,由导入器一起同步进货架;只同步了着色器、清单还是旧的,身份就对不上,
桥会退回只写同名参数并说明原因。

**贴图 Blender → Painter**(也是给新纹理集打底的办法,比如补回一张脸,选中那一个集推送 /
拉取):清单的 `inputs` 写着
着色器的每个输入是材质哪张贴图的哪几个分量、过什么运算 —— 导入器把游戏材质导进 Painter 读的也是这张表。
Painter 的 Python 做不了逐像素运算,所以按表开单请 Blender 切图(分量拷贝、取反、Unity 法线解包),
回来的图这样落地,**一层不删**:

- 可画的通道装进集**最底下**一个桥自己的填充层 `Blender: <材质名>`:下次同步找到它重新填,不叠第二层;
  已有的图层都在它上面,原来盖住哪里还盖住哪里。栈里没有的通道按清单写的格式加上,用户通道以输入的
  语义名作标签(和导入器一致;Painter 导出时按这个标签给文件起名)。
- 和 Painter 自己的烘焙合成的输入(切线法线、AO)当这个集的网格图 —— **只在集里还没有时**才设,
  别人烘的图不归桥换。
- 着色器整张读的图(渐变、查找表、SDF、打包剩下的位)写进这个集自己的着色器实例的参数。
- 字节相同的图不重复导入(哈希记在工程元数据里)。
- Painter 是**用到时**才从导入的源文件读图(存盘时才嵌进工程),而送来的图是传输件、会被回收;
  所以导入前先在 `%LOCALAPPDATA%\RuriDccBridge\painter_imports\<进程号>` 留一个硬链接,留到工程关闭。
  Painter 不在了的文件夹,下次有 Painter 用到时清掉。

## 贴图

导出的贴图写进 .blend 旁边的 `textures` 文件夹(偏好设置里可改名),Blender 直接引用这些文件,
所以贴图跟着 .blend 走。色彩空间由知道通道格式的一侧写进记录:`sRGB8` 是唯一按 sRGB 编码存储的
格式,其余一律按原值用(Blender 的 `Non-Color`)。

**生成材质不吃散通道。** 它采样的是生成时那套贴图(底色图 alpha 里装不透明度、打包法线、光泽图的
alpha 是 1−粗糙度……),按自己的记录读。哪个通道进哪张图的哪个分量、过什么运算,是 Painter 货架上
着色器清单的 `reads` —— Painter 侧着色器边画边从通道拼出这些图用的就是这张表;身份与材质声明一致时,
Painter 把它连同「每个输入在这次导出里是哪张图」写进贴图记录,Blender 逐像素照做,拼成
`<纹理集>_<槽>.png` 写进 `textures`,换进材质记录,材质运行时跟着记录重新接线。不发明数据:

- Painter 栈里**没有**的通道(比如外包工程没建高光强度、自发光遮罩),那一分量保留材质自己贴图里的值;
- 清单说原样保留的分量(一张图打包剩下的位),取材质自己的贴图;
- 一张图用到的 Painter 通道**全是一个值**(没画过),材质保留自己的那张;整个纹理集都这样,就报「没画」。

身份不一致(或货架上没清单)时不拼,报原因 —— 用别的一代着色器的表拼,每个分量都会错位而且一声不响。

## 动作:送去 Cascadeur,做完拿回来

N 面板的 Cascadeur 一节:把选中的绑定和它当前的动作一起发过去(骨架跟着表演走),在 Cascadeur
里做,再取回来 —— 取回的曲线**按骨名落到已有的绑定上**,临时导入物当场删掉。Cascadeur 不驻留:
桥召唤它跑一条命令,它做完就退出。

两个方向都只用 glTF(Cascadeur 自带 `csc.glb` 两个方向的门),一份模型不存两种编码。

## 装进三个宿主

```bash
python -m RuriBridge.Kernel.cli install ^
    --painter-plugins "<Painter 用户 python>/plugins" --enable-painter-plugin ^
    --cascadeur "<Cascadeur>/cascadeur.exe"
```

安装器走一遍花名册,每一行自己说怎么装:检出本体(Blender)、目录联接(Painter)、往它自己的
命令目录写一扇门(Cascadeur)。`--enable-painter-plugin` 写 Painter 的 `launch_at_start`,
**Painter 必须关着**。

所有应用用同一个会话名(默认 `default`,可用 `RURI_BRIDGE_SESSION` 覆盖)就在同一块竞技场上;
会话根默认 `%LOCALAPPDATA%\RuriDccBridge\sessions`,可用 `RURI_BRIDGE_ROOT` 覆盖。

## 命令行

```bash
python -m RuriBridge.Kernel.cli status                 # 控制块:每个通道的代次/确认/载荷字节
python -m RuriBridge.Kernel.cli inspect --channel mesh@Blender
python -m RuriBridge.Kernel.cli verify-mesh            # 重读发布的表面并逐项判定
python -m RuriBridge.Kernel.cli textures --into <目录>  # 列出 Painter 最新一批贴图,可另存
python -m RuriBridge.Kernel.cli sessions / remove
python -m RuriBridge.Kernel.cli publish-mesh   --blender <blender.exe> --blend <场景>
python -m RuriBridge.Kernel.cli request-export --blender <blender.exe> --blend <场景>
python -m RuriBridge.Kernel.cli pull-textures  --blender <blender.exe> --blend <场景>
```

`verify-mesh` 是判据不是打印:每个面角都落在顶点 / UV / 法线表内,每个物体画进每个纹理集的面数
与记录一致,声明的包围盒真的包住位置,记录带着坐标系。

驱动动作都是**让 Blender 去发**:每条通道只有一个写者,命令行变成第二个写者就会和插件抢代次号。

## 通道与记录

通道名是算出来的:`<主题>@<说话的人>`。谁能说谁能听不是表,是能力的连接 —— 加一个应用是
花名册里多一行。

| 主题 | 谁能说 | 谁能听 | 语义 |
|---|---|---|---|
| `mesh` | Blender | Painter | 队列 |
| `tex` | Painter | Blender | 队列 |
| `anim` | Blender、Cascadeur | Blender、Cascadeur | 队列 |
| `shade` | Blender、Painter | Blender、Painter | 状态 |
| `here` | 三个都能 | 三个都能 | 状态 |
| `ask` | 三个都能 | 三个都能 | 队列 |

**队列**是不可变 generation 目录,未确认的不丢;**状态**是一个槽,后写覆盖前写。确认位按听众
分开,发布者回收时取所有真正在听的人的最小值,并保住每个听众最后确认的那一代。

记录格式带版本号;读到别的版本直接拒绝,不兼容旧形状。
