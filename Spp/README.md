1. .spp 是 HDF5 文件,绘制内容的真源是其中的 paint/document.bin,一条 Painter 自描述的数据流,里面没有像素。

2. 像素住在文档之外:texture-cache 下按材质存的图层渲染缓存、烘焙出的网格贴图、resources 下按内容寻址的导入图片,文件大小主要是它们(推断,没按数据集量过占比)。

3. 图层是一叠动作:绘画、橡皮、涂抹、克隆、投影绘画、填充、多边形填充、滤镜,一个绘画动作带一份笔刷和一串笔触。

4. 一笔(DataStroke)存的是输入折线:每点屏幕上的 x、y(0 到 1)、时间、点类型,另有每点笔压与倾斜(鼠标画的为空);它不是曲线,也不存印章。

5. 一笔还存着画它时的视图:3D 视图里画的存相机的视图矩阵与投影矩阵,UV 视图里画的存 UV 坐标;另存对称副本矩阵、随机种子、防抖距离。

6. 印章的大小、间距、抖动、旋转、形状(程序化包或位图)、混合都在笔刷里,不在笔触里;间距是笔刷发射器里的一个浮点数,界面里调的 5 在文件里是 0.05。

7. 重放一笔时先沿折线按间距重新采样出印章位置:30 个点的折线、间距 1.2 倍笔刷大小,只落了 3 个印章,所以间距决定每笔有多少印章,不是录制的点数。

8. 3D 视图里画的每个印章用笔触存的相机从屏幕位置射线投到当前网格上,把形状写进图层在该纹理集里的贴图;UV 视图里画的直接按 UV 坐标放。

9. 打开工程不重放笔触:改了文件里的笔触数据再打开,画面不变,换网格后才按新笔触重放,打开用的是缓存。

10. 让缓存失效的操作会把笔触整个重放,我只实测了换网格;重放代价正比于印章总数,印章总数是各笔折线长度除以(间距 × 笔刷大小)之和,间距从 20 调到 5 就是 4 倍。

11. 对称副本不另存笔触,同一笔带一个矩阵,重放时再画一遍,带副本的笔触印章数翻倍(真工程里有 6503 笔)。

12. 日常画图的卡主要不在重放,在每画一笔上面整条图层栈要重新合成,代价正比于层数、通道数、分辨率、UV 格数,滤镜与生成器另走 Substance 引擎,所以关掉上面的图层就不卡(推断:没剖析过 Painter 内部,只对上了关掉上面图层就不卡的反馈)。

13. 笔触本身很小:真工程笔触约 4.2 万笔,数过点数的 3.6 万笔共约 390 万个点,每点约 16 字节,合计约 60 MB 上下,而整个工程文件有 1.4 GB,所以存点不是文件大的原因,也不是卡的原因。

14. 设计上最差的是笔触存屏幕空间加作画相机,不是表面空间:网格、UV、模型位置任何一个变了,重放就落到别处(测试模型不修时 86% 到 99% 的笔触像素错位),数据本来可重放可改写,Painter 却没提供换算。

15. 多边形填充存的是相机射线或 UV 视图里的点和框加粒度(三角形、多边形、网格元素、UV 块),不存任何三角形编号,换网格后选到什么靠重新求交。

16. 每个绘画动作带自己的一整份笔刷、程序化源和调节项,互不共享:真工程文档里约 1.1 万个笔刷、1.1 万个程序化源、4 万个调节项。

17. 绘画层的内容只由这份动作日志定义,文档里看不到把历史折成像素的结构,画得越多重放与重算越重。

18. 笔触是文件里的数据,所以能在文件里改:UV 布局换了、网格没动时,Spp/retarget 把 UV 视图里的笔触点按同一块表面搬到新版面、版面说不清的点选换成紧贴多边形的相机点选、走 UV 的填充改成 UV 集到 UV 集投影,一个像素不烘焙;网格换了、布局没动时不改笔触,用第 27 条的画布。

19. 真工程(1.5 GB、19 个材质)上给一个材质做画布(整份克隆、改文档、写 FBX)约 17 秒,Painter 打开工程加换网格重放约 52 秒。

20. 没验证:录制端是否按间距抽稀点(要看真工程里相邻点的距离与笔刷大小乘间距的关系)。

21. 没验证:除换网格外还有哪些操作让缓存失效并触发整体重放。

22. 没验证:存盘不带缓存时,打开是否按笔触重算。

23. 没验证:图层栈重新合成的失效范围与各部分耗时。

24. 面从一个材质换到另一个材质时,复制过去的图层里在 UV 视图画的笔触要按面现在的位置搬:只留落在搬来的面上的点,断开的几段各成一笔,笔压与倾角按点跟着切;点选只留搬来的面(Spp/retarget/faces,命令 carry)。

25. 三维视图画的笔触和相机点选在复制品里不动,但命中只看目标材质自己的面,原来挡在前面的源材质的面不在了,会多画(源材质读着画布时没有这个问题,见第 31 条)。

26. Spp/layers 不经 Painter 读出哪些图层里有画(笔触、路径、多边形填充),桥拿它判断一个根层复制时要不要修。

27. 网格换了、UV 布局没动时不改笔触:材质整份克隆成画布(名字加 `~canvasN`),栈的所有层放进一个末尾带锚点的文件夹,原材质的栈换成一个填充层,每个通道一个引用源指向那个锚点,UV 投影,逐纹素搬,不重采样(Spp/retarget/canvas)。

28. 画布的网格是旧网格:从工程自己的场景取回材质的网格,按导入变换反算回 FBX 坐标,原名原位,材质名改成画布名,画布上每一笔都重放在画它时的表面上;导入变换是 Painter 第一次导入时按包围盒定的一个等比缩放加平移,保留笔触换网格时它不变。

29. Painter 的接口把一个纹理集的层读另一个纹理集的锚点当成环拒绝,文档里这样写却能存、能开、能算;接口读这样的引用,锚点给的是 None,实例化(`layerstack.instantiate`)这样的层会把引用清成无,所以这种层不能经实例搬。

30. 画布的网格必须随每一版表面一起进 FBX:Painter 换网格时丢掉表面里没有的纹理集。

31. 文档里别处指向搬进画布的层的引用(别的材质里的实例)要改指克隆里的层,否则那些实例什么也显示不出(真工程里搬来的面显示源材质层的文件夹就是实例,不改时大片内容丢了)。

32. 几何遮罩按网格名存,一个物体带几个材质时场景里有几个同名网格,所以画布的网格必须原名;FBX 里同名的模型 Painter 照收。

33. 画布克隆出来的网格贴图设置指向与原材质同一批资源,Painter 照读(实测画布与原材质的 `get_mesh_map_resource` 给同一个地址)。

34. Painter 没有隐藏纹理集的 Python 接口,只有纹理集列表里每行的眼睛;状态不存盘,换网格和开工程都会重置。

35. 读画布的填充当作排在画布布局里的内容:改布局时和图片填充一样改读保着旧布局的那套 UV;切线法线在转了向的孤岛上保持旧方向。

36. 画布模板(`retarget/canvas_templates.bin`)是 Painter 自己写出的对象(`cli templates` 从一个 Painter 存的工程里做出来),用前核对类型定义与文档一致,不一致就拒绝。
